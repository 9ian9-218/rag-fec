# 项目描述（简历版，已更新至最新功能）

> 更新日期：2026-08-23 ｜ 字数 506（原版 431）

**S（情境）**：传统单向量检索 RAG 存在实体关系理解弱、检索策略固定、文档重复索引、输出忠实度不足等问题，领域问答效果达不到业务要求。
**T（任务）**：搭建知识图谱 + 向量双检索 RAG 系统，实现文档自动入库、检索策略自适应切换，构建完整评测与迭代埋点体系，提升问答召回、忠实度等核心指标。
**A（行动）**
1. 采用 Neo4j 存实体关系、Milvus 存文本向量，MinerU 多格式解析入库，MD5 增量避免重复索引，文档上传/更新异步任务化；FastAPI 封装问答接口；
2. 设计问题难度自适应路由，PEFT 微调 Qwen3.5-0.8B 作为路由模型，自动切换 5 种检索策略；关键词过滤、BGE 重排降噪；
3. 引入 Redis 缓存与分布式锁保障并发一致，查询/索引 LLM 并发隔离、限流重试提升在线稳定，封装在线 Embedding，自研 Web 问答前端；
4. 搭建全链路评测体系，RAGAS 指标 + SQLite 在线遥测批量落库，观测延迟、图谱空率、重排过滤率驱动迭代。
**R（结果）**：Recall@5＞0.8，NDCG@5＞0.7；RAGAS 各项指标均大于 0.7，问答忠实度约 0.95；支持文档增量更新，具备线上埋点迭代能力。
